## Existing-data preparation

`tools/prepare-legacy-migration.py` accepts an offline SQLite snapshot or SQL export with the existing `hrdesk_objects`/`hrdesk_sequences` schema. It produces a private mode-0600 SQL import outside Git, never connecting to a remote service. JSON, IDs, versions and timestamps are retained. Existing reference counters and reference numbers seed the new counters without decreasing them. Source tables remain unchanged. Repeating the same import is safe while target rows match; conflicting target records raise a database constraint error before record inserts instead of being overwritten. The import guard is a fail-stop check, not a promise of a single D1 transaction; after any failed import inspect staging before retrying.

Apply core migration 0001 to an authorized staging database before applying the generated import SQL. This is an explicit migration of the data contract, not a transparent replacement of the old API. No real snapshot has been read, exported or migrated in this task. Keep snapshots and generated SQL outside Git and company-public storage. Validate counts, references and user-visible data against an approved staging copy, and retain the old tables for rollback. Do not export or modify production as part of these instructions without separate authorization.

```sh

python3 tools/prepare-legacy-migration.py --sqlite /private/source.sqlite --output /private/staging-import.sql
```
